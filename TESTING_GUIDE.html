1. Prerequisites & Starting the Application

Two ways to run — choose one:
Docker Recommended. Consistent on any OS. Requires Docker Desktop.
Local Requires .NET 8 SDK + Azure Functions Core Tools v4. Works on Windows without Docker.
Windows quick-start (no Docker): Double-click START-HERE.bat in the project root. It checks prerequisites and opens both services in separate windows automatically. Or run .\START-HERE.ps1 in PowerShell.

Option A — Docker (recommended)

1
Install Docker Desktop from docker.com if not already installed.
2
Open a terminal and navigate to the project root: 
cd "ABCRetailWebApp"
(the folder containing docker-compose.yml)
3
Build and start both containers: 
docker compose up --build
First run takes ~3–5 minutes (downloads base images, restores NuGet packages).
Subsequent runs use the cache and start in ~30 seconds.
4
Wait until you see both services healthy: 
abcretail-functions  | BlobUploadFunction: [POST] http://localhost/api/BlobUploadFunction
abcretail-functions  | TableWriteFunction: [POST] http://localhost/api/TableWriteFunction
abcretail-functions  | OrderProcessingFunction: queueTrigger
abcretail-functions  | StockAlertsFunction: queueTrigger
abcretail-functions  | TransactionLogFunction: queueTrigger
abcretail-webapp     | Now listening on: http://[::]:8080

Option B — Local (without Docker)

1
Install prerequisites:
  • .NET 8 SDK
  • Azure Functions Core Tools v4: 
    npm install -g azure-functions-core-tools@4 --unsafe-perm true
2
macOS only — fix quarantine warning (one-time, if you see "Apple could not verify…"): 
xattr -d com.apple.quarantine "ABCRetailWebApp/bin/Debug/net8.0/ABCRetailWebApp"
3
Terminal 1 — start the Functions runtime: 
cd ABCRetailWebApp.Functions
func start
4
Terminal 2 — start the web app: 
cd ABCRetailWebApp/ABCRetailWebApp
dotnet run
URLs used throughout this guide:
Web app: http://localhost:5191
Functions: http://localhost:7071

2. Azure Functions Tests

Run these from a terminal. curl is available on macOS, Linux, and Windows 10+. Alternatively use Postman.

Windows users: Use PowerShell (not Command Prompt) to run the curl commands below — PowerShell 5+ ships with curl built in. If you see 'curl' is not recognized, open PowerShell and retry. Single quotes inside -d must be escaped on Windows; the easiest fix is to save the JSON to a file and use -d @body.json instead.

Test 1 — TableWriteFunction

POST http://localhost:7071/api/TableWriteFunction

Upserts a product to the Products Azure Table, publishes a message to the product-events queue, and appends to the file log.

1a — Happy path (create product)

curl -s -X POST http://localhost:7071/api/TableWriteFunction \
  -H "Content-Type: application/json" \
  -d '{
    "partitionKey": "Electronics",
    "rowKey": "prod-006",
    "productName": "Wireless Earbuds",
    "description": "True wireless earbuds with active noise cancellation and 24-hour battery life.",
    "price": 1499.00,
    "stockQuantity": 50,
    "category": "Electronics",
    "brand": "SoundCore",
    "isAvailable": true,
    "createdAt": "2025-01-01T00:00:00Z"
  }'
Expected response200 {"success":true,"rowKey":"prod-006"}
Azure TableRow with PartitionKey=Electronics, RowKey=prod-006 exists in Products
Portal: Storage account abcretail2026st10531590 → Tables → Products → Query with PartitionKey eq 'Electronics'
Queueproduct-events has a new message containing ProductCreated
Portal: Storage account → Queues → product-events → Peek
File logapplogs/logs/product-events-{today}.log has a PRODUCT_CREATED line for prod-006
Portal: Storage account → File shares → applogs → logs → product-events-{today}.log → View/Download

1b — Upsert idempotency (run same row key again with different price)

curl -s -X POST http://localhost:7071/api/TableWriteFunction \
  -H "Content-Type: application/json" \
  -d '{
    "partitionKey": "Electronics",
    "rowKey": "prod-006",
    "productName": "Wireless Earbuds",
    "price": 1299.00,
    "stockQuantity": 45,
    "isAvailable": true,
    "createdAt": "2025-01-01T00:00:00Z"

Expected response200 {"success":true,"rowKey":"prod-006"}
Azure TableSame row now has Price = 1299.00 and StockQuantity = 45 — no duplicate row
Portal: Storage account → Tables → Products → click the prod-006 row to confirm updated values

1c — Missing required fields

Test 2 — BlobUploadFunction

Uploads a product image to the productimages blob container and returns the blob name. Also appends to the file log.

3. End-to-End Application Test

With both the web app and functions running, walk through the full customer and admin flows.

Customer Flow ───────────────────────────────────────────────────── 1. Open http://localhost:5191 2. Click "Register" → create a customer account 3. Browse products on the home page 4. Click "Add to Cart" on any product 5. Click the cart icon → review cart 6. Click "Checkout" 7. Enter any card details (e.g. 4111 1111 1111 1111 / 12/26 / 123) 8. Click "Pay Now" Expected in functions log (within ~5 seconds): [OrderProcessingFunction] Order audit saved. OrderId: ORD-... [TransactionLogFunction] Transaction logged to table. (if stock hit 0) [StockAlertsFunction] Stock alert saved to table.
Admin Flow ───────────────────────────────────────────────────── 1. Open http://localhost:5191 2. Log in with admin credentials (check seed-data.json for the admin email) 3. Navigate to Admin → Add Product 4. Fill in product details and optionally upload an image 5. Click "Add Product" Expected: → Redirected to Inventory immediately (no hang) → New product appears in the inventory list → In functions log: [TableWriteFunction] Product upserted. → If image uploaded: [BlobUploadFunction] Blob uploaded. → product-events queue has a new ProductCreated message
Admin Queue Management ───────────────────────────────────────────────────── 1. Admin → Order Queue 2. Click "Process Next" to dequeue and mark an order as Shipped 3. Admin → System Logs — view file log entries 4. Admin → Dashboard → "Verify Inventory Stock" — cross-references stock-alerts-queue with current product stock levels

4. Fallback / Resilience Test

Verifies the web app never hangs or shows an error when functions are unavailable.

Docker

docker compose stop functions

Local

Close the func start terminal.

1
With functions stopped, go to Admin → Add Product and submit a new product with an image.
2
Expected:
  • Admin is redirected to Inventory within ~3 seconds — no hang, no error page
  • Product appears in the inventory list (direct table write succeeded)
  • Image shows as a placeholder (BlobUploadFunction was unreachable)
  • No 500 error, no exception shown to the user
3
Restart functions: docker compose start functions (or re-run func start).
The fire-and-forget TableWriteFunction call will have already timed out and been discarded — this is expected. The product was already written directly by the web app. The audit log entry and queue message for that product will be missing, which is the documented trade-off of the fire-and-forget pattern.

5. Viewing Functions & Logs in Azure Portal

These functions run locally (Docker or func start) and connect to the real Azure Storage account. The Azure Portal does not show local function invocations in Application Insights — but you can see the functions listed, browse their code, and read all side-effects (tables, queues, blobs, file logs) that the local run produced.

Note: Because the Function App resource has not been deployed to Azure (functions run locally only), the Monitor → Invocations and Application Insights tabs in the portal will be empty. All runtime evidence lives in the storage account — covered in Section 6.

Navigate to the Function App in Azure Portal

1
Go to portal.azure.com and sign in.
2
In the top search bar type Function App and select it from the results.
3
If a Function App resource exists for this project, click it. If none exists yet, the functions are running locally only — skip to the Reading local function output section below.
4
In the left sidebar of the Function App, click Functions. You will see all five functions listed:
  • TableWriteFunction — HTTP trigger
  • BlobUploadFunction — HTTP trigger
  • OrderProcessingFunction — Queue trigger
  • StockAlertsFunction — Queue trigger
  • TransactionLogFunction — Queue trigger

View a function's invocation history & logs (deployed only)

1
Click any function name, e.g. OrderProcessingFunction.
2
Click Monitor in the function's left sidebar. The Invocations tab shows a timestamped list of every execution — green for success, red for failure.
3
Click any row in the invocations list to open the invocation detail. This shows the full log output for that single run, including any ILogger messages the function wrote (e.g. Order audit saved. OrderId: ORD-...).
4
Click the Logs tab (next to Invocations) for a live streaming log — equivalent to watching the terminal when running locally.

Reading local function output (no deployed Function App)

When running locally, function log output appears directly in the terminal running func start (or in the Docker container log). To see it:

How you're runningWhere to see function logs
Local (func start) The terminal window where you ran func start. Each function execution prints timestamped lines like:
[2026-09-16 11:03:17] Executing 'TableWriteFunction'
[2026-09-16 11:03:17] Product upserted. RowKey: prod-006
Docker Run docker compose logs -f functions in a terminal to tail the functions container log in real time. Or view it in Docker Desktop: open the abcretail-functions container → Logs tab.

Reading the persistent file logs written by the functions

The functions also write structured logs to Azure File Share, which you can read any time in the portal regardless of whether the functions are currently running:

Log fileWritten byPortal path
applogs/logs/product-events-{date}.log TableWriteFunction, BlobUploadFunction portal.azure.com → Storage accounts → abcretail2026st10531590 → Storage browser → File shares → applogs → logs → click the file → View/Download
applogs/transactions/transactions-{date}.log TransactionLogFunction portal.azure.com → Storage accounts → abcretail2026st10531590 → Storage browser → File shares → applogs → transactions → click the file → View/Download
Tip — reading logs in the web app: You can also read the file logs without leaving the app. Log in as admin → Admin → System Logs. This page reads directly from the Azure File Share and displays the same log content in the browser.

Using az-cli container (Docker only)

# Check Products table
docker compose --profile tools run --rm az-cli \
  az storage entity show --table-name Products \
  --partition-key Electronics --row-key prod-006 -o table

# Check blob exists
docker compose --profile tools run --rm az-cli \
  az storage blob show --container-name productimages \
  --name "product_prod-006.jpg" \
  --query "{name:name,size:properties.contentLength}" -o table

# Peek product-events queue
docker compose --profile tools run --rm az-cli \
  az storage message peek --queue-name product-events \
  --num-messages 5 -o table

7. Cleanup After Testing

Remove test data from Azure Portal to keep the storage account clean:

  • Tables → Products → delete row prod-006 (or restore original price 1499.00 if preferred)
  • Tables → OrderAudit → delete row ORD-20250301-TN003
  • Tables → StockAlerts → delete row prod-015
  • Tables → Transactions → delete test rows
  • Containers → productimages → delete product_prod-006.jpg
  • Queues → clear product-events and transaction-queue if needed

Stop Docker containers

docker compose down
